Single-page-feeling (technically multi-route) landing site for **Dr. Sara Shuttari**, Cybersecurity & Information Technology Professional, under the "Cyber Battalion" brand.

**Read `PLAN.md` first** — it contains the full agreed spec: stack, palette, section-by-section breakdown, the interactive workshops panel, data model, and photo folder structure. The "Since this was drafted…" note near the top and the "Decisions already made" section at the bottom are load-bearing: they record changes made after the original plan was written and explicit decisions not to re-litigate. When PLAN.md and the live code disagree, treat the code as current and the mismatch as worth flagging, not silently "fixing" in either direction.

The site is built and verified (build, lint, responsive, a11y — see PLAN.md's Verification checklist). The main outstanding gap is real workshop photos — `public/images/workshops/<slug>/` still holds placeholders (see its README.md); collaborations, gallery, and most of team now have real assets.

**All photo/logo collections live under `public/images/<collection>/`** (`collaborations/`, `gallery/`, `team/`, `testimonials/`, `workshops/`, `welcome-modal/`) — moved there from directly-under-`public/` on 2026-08-05 for organization. `logo.png`, `sara.png`, `bg.svg`, and `icon.png` (the last is actually `src/app/icon.png`, a Next.js file-convention route, not really in `public/` at all) deliberately stayed put — they're single fixed site-wide assets, not "image folders." If you add a new photo collection, put it under `public/images/`, not directly under `public/`.

## Architecture

- **Next.js 16 App Router, TypeScript, Tailwind v4, React 19.** No longer purely static — there's one real backend endpoint: `src/app/api/contact/route.ts`, a Route Handler that sends the Contact form via `nodemailer` over Gmail SMTP (replaced the earlier `mailto:` approach, which the client reported as "not working"). Everything else is still a static frontend (no database, no other API routes).
  - Auth reads `process.env.GMAIL_USER` / `GMAIL_APP_PASSWORD` — **never hardcode these**. Local dev value lives in `.env.local` (gitignored, never commit it); the same two vars must be set in the production host's environment config (e.g., Vercel project settings) for this to work when deployed.
  - **Gmail requires an App Password, not the account's normal login password** — Google removed "less secure app" SMTP access entirely, so a regular password gets a hard `535-5.7.8 Username and Password not accepted` rejection regardless of 2FA status (confirmed with an actual failing test send, then a working one after switching to a real App Password — "CyberBattalion_web_query", generated 2026-08-04). If `GMAIL_APP_PASSWORD` ever stops working again, this is almost certainly why — the fix is generating a new one at https://myaccount.google.com/apppasswords (requires 2-Step Verification to be on for that Google account first), not debugging the code.
  - `ContactForm.tsx` POSTs JSON to `/api/contact` and shows submitting/success/error state; on error it falls back to telling the user to email `info@cyberbattalion.in` directly rather than silently failing.
- **Routing:** `src/app/page.tsx` is the homepage and composes `WelcomeModal → AnnouncementMarquee → Hero → Collaborations → Highlights → SeminarsSection → GallerySection → TestimonialsSection → TeamSection → CentreOfExcellence → ContactSection` (`WelcomeModal` renders `null` most of the time — see its own note below — so its position in the list doesn't affect layout, only mount order). `src/app/about/page.tsx` renders the `About` component as a real but currently unlinked route (not in Navbar/Hero nav — deliberately hidden per client request, don't re-add the nav link without being asked).
- **`Navbar`/`Footer` live in `src/app/layout.tsx`**, not in `page.tsx`, since they're shared chrome across the (technically) multi-page site. Nav switches from hamburger to full horizontal links at `lg` (not `md`). Nav intentionally omits `#seminars` (a lightweight supplementary block, not worth a top-level link) — don't assume every homepage section has a nav entry. The "Excellence" nav label is a shortened form of "Centre of Excellence" (space constraints); the section heading itself is unchanged. Section anchors used for in-page nav/CTAs: `#top`, `#highlights`, `#collaborations`, `#seminars`, `#gallery`, `#testimonials`, `#team`, `#centre-of-excellence`, `#contact`. (`#about` still exists on its own page but isn't a homepage anchor.)
- **Design tokens** (`--bg`, `--maroon`, `--navy`, `--gold`, `--muted`) are defined as CSS custom properties in `src/app/globals.css` under `@theme` and consumed as Tailwind utilities (`text-maroon`, `bg-maroon-dark`, `text-gold-text`, etc.) — don't hardcode hex colors in components. Fonts: `Fraunces` (serif, `--font-fraunces`, headings) and `Inter` (`--font-inter`, body), loaded via `next/font/google` in `layout.tsx`. `@keyframes marquee` in `globals.css` drives both `AnnouncementMarquee.tsx` and (if re-added) any other scrolling ticker — it was removed once when Collaborations dropped its marquee, then reinstated for `AnnouncementMarquee`; don't remove it while that component exists.
- **The interactive centerpiece is `Highlights.tsx` → `WorkshopsPanel.tsx` → `Lightbox.tsx`:**
  - `Highlights.tsx` owns an `open` boolean that expands/collapses a full-width panel (CSS grid-rows trick + `inert` for a11y) directly beneath the highlight cards, rendering `WorkshopsPanel` inside it, and scrolls it into view on open (respecting `prefers-reduced-motion`). It also has its own independent expand/collapse state for a "Projects" card, which expands *in place* (not below-grid like Workshops) and ends in a "Register Now" link to `#contact` — don't conflate the two toggles. Cards, in order: Workshops (interactive) → Internship & Placements → Projects (interactive) → FDPs → Intellectual Connects. Grid uses `items-start` so an expanded card doesn't stretch its row-mate.
  - `WorkshopsPanel.tsx` reads `src/data/workshops.ts` (40 entries, typed by the `Workshop` type in that file), handles search/filter (matches college/name/topic, resets to page 1) and pagination (5/page). Clicking a thumbnail opens `Lightbox.tsx`, scoped to that workshop's `photos` array.
  - Workshop photo folders live at `public/images/workshops/<slug>/`, where `<slug>` must match the entry's `slug` field exactly — pre-created for all 40 entries even though most still hold placeholder content. **The client sent a real (but truncated) list of seminar/college names over WhatsApp that hasn't been reconciled with this placeholder data yet** — get the untruncated list before touching `workshops.ts` college names, to avoid redoing it.
  - `Lightbox.tsx` is **generic**, not workshop-specific: it takes `{ photos, initialIndex, title, subtitle?, fallbackSrc, onClose }`, not a `Workshop` object. `GallerySection.tsx` reuses it too. If you need a lightbox somewhere new, pass these props rather than adding a workshop dependency.
- **`src/hooks/useDialogBehavior.ts`** is shared modal a11y logic (focus dialog on open, Tab trap, Escape/optional ArrowLeft-ArrowRight, body scroll lock, restore focus on close) used by both `Lightbox.tsx` and `WelcomeModal.tsx`. It takes an **`active: boolean`** param that's easy to get wrong: `Lightbox` is unmounted entirely by its parent on close, so it can pass `active: true` unconditionally, but `WelcomeModal` manages its own `open` state and returns `null` rather than unmounting — it **must** pass `active: open`. This isn't cosmetic: a real bug shipped and was caught during verification where `active` didn't exist yet, the effect only ran on mount (`useEffect(..., [])`), and closing `WelcomeModal` left `document.body.style.overflow: hidden` permanently set (page scroll dead) because a `null` render doesn't unmount the component or re-run a mount-only effect. If you add a third dialog-like component, make sure it passes the *real* open/closed state, not just `true`.
- **Missing-image handling:** `ImageWithFallback.tsx` wraps `next/image` with an `onError` handler that swaps to a fallback src (`_placeholder.svg`) client-side, so incomplete photo/logo folders never produce a broken image. Use it (not raw `next/image`) anywhere a src comes from a data file. `TestimonialAvatar.tsx` / `TeamPhoto.tsx` are the people-photo equivalent (shared `getInitials()` in `src/lib/initials.ts`) — but they go a step further: if `photo` is falsy they render the initials block **without attempting an `<Image>` at all**, not just on error. This is deliberate — every `testimonials.ts`/`team.ts` entry currently has `photo: ""` (no real photos yet), and the user explicitly asked not to fire fetches (and 404s) for files that don't exist. Set a real `photo` path once one exists; don't re-introduce eager fetching before that.
- **`Collaborations.tsx`** renders `src/data/collaborations.ts` (6 entries, order is client-specified: Lords, ASTI, HMA, Cyverra, HCL, MANUU — don't re-sort) as a static single-row grid (`lg:grid-cols-6`) of logo cards — PLAN.md's marquee/auto-scroll description for this section is superseded (see the note at the top of PLAN.md). Cards are clickable (`url` field) only where an official site was confidently verified; HMA CyberTech and Cyverra Global Technologies LLP turned up no confident match and are intentionally left unlinked pending the client.
- **`SeminarsSection.tsx`** reads `src/data/seminarInstitutions.ts` — a partial list of real institution names from the client's WhatsApp message (truncated by "Read more," full list not yet received; `seminarListIsPartial` drives the trailing "and more..." pill). This is separate from `workshops.ts`'s placeholder college names — don't conflate the two until the full list arrives and a decision is made on reconciling them.
- **`TestimonialsSection.tsx`** reads `src/data/testimonials.ts` (9 people, names from the client's WhatsApp list) as a horizontal snap-scroll slider (dots + arrows, `IntersectionObserver`-driven active state) rather than a static grid. `designation` is intentionally an empty string pending the client ("Designation pending" placeholder) — **don't invent one**. `quote` currently holds **draft placeholder copy the user explicitly asked to be written now and replaced later** — safe/generic praise, no fabricated specifics — flag to the user before treating any of it as final, client-approved wording.
- **`TeamSection.tsx`** reads `src/data/team.ts` (5 names from an internal review doc) — **light background** (not dark navy, that was an earlier iteration), tall portrait cards (`aspect-[4/5]`) in a snap-scroll slider, modeled on a reference "Meet our team" design the user shared. Deliberately did **not** copy that reference's CTA buttons or logo row — the buttons didn't map to any real action here, and the logos would just duplicate `Collaborations.tsx`. No roles were given, so cards show a generic "Cyber Battalion Team" line rather than invented titles. 4 of 5 members (Abdul Sameer, Zayed Ali, Shaik Ubaid Ali, Roshan) have real photos in `public/images/team/` as of 2026-08-05; Mohan is still initials-only (`photo: ""`).
- **`GallerySection.tsx`** reads `src/data/gallery.ts` (45 **real** photos across 5 categories — `LSA | MJS | LIET | Spoorthy | TRR`, sourced from `public/images/gallery/{lsa,mjs,liet,Spoorthy,trr}/`, note the capital S) as **tabs (All + one per category) filtering a true Pinterest-style masonry**. This is a **JS column-array layout, not CSS `columns`** — `distributeColumns()` walks photos in order and drops each into whichever column currently has the least accumulated height (using `height/width` as a relative-height proxy), matching real reading-order masonry rather than CSS multi-column's fill-one-column-first behavior. Column count is 2 below 640px, 3 above, tracked via `matchMedia`. Each entry's `width`/`height` (read with `sips`, see `public/images/gallery/README.md`) must stay accurate — it directly drives which column an image lands in, not just cosmetic. **Paginated, not fully rendered**: only `visibleCount` (starts at `PAGE_SIZE`=12, `+12` per "Load More" click, reset on tab change) photos are sliced in before distributing into columns; a bottom fade (`bg-gradient-to-t from-bg`) plus the Load More button only render while more remain. The slice happens *before* masonry distribution, so column balance is always computed over just what's visible, not the full set.
- **`WelcomeModal.tsx`** is a promotional popup (title "Upcoming: Dubai Internship at LSA", 6-image carousel from `public/images/welcome-modal/upcoming/`, dot nav, close button, click-outside-to-close) that appears once per `sessionStorage` (`welcome-modal-shown` key), 2s after the homepage mounts (`src/app/page.tsx` only — not on `/about`). It has **no registration CTA** — the QR code (`public/images/welcome-modal/reg_qr.jpeg`) and Google Form link the user provided are for the *weekend Cyber Security batch* (a different, unrelated program that already had its own announcement — see `AnnouncementMarquee.tsx` below), not the Dubai internship. Don't attach that link/QR to this modal; the user explicitly corrected that mistake once already ("Register event is different and upcoming event is different").
- **`AnnouncementMarquee.tsx`** is a scrolling ticker between the header and Hero announcing weekend Cyber Security batch registrations at LSA. `REGISTER_HREF` is a real Google Form (`https://forms.gle/8j9k9VQKTuxggxr7A`, provided by the user 2026-08-05) — this is the *only* place that link belongs; see the `WelcomeModal.tsx` note above for why it's deliberately not reused there.
- **`Highlights.tsx`** now has 5 cards in a `sm:grid-cols-2 lg:grid-cols-3` grid (not the plain 2×2 from before) — the 5th, "Intellectual Connects," has placeholder copy since the client hasn't defined what this feature actually is yet; confirm with her before treating its wording as final.
- **Data files** (`workshops.ts`, `collaborations.ts`, `gallery.ts`, `testimonials.ts`, `team.ts`, `seminarInstitutions.ts`) are plain typed arrays, not fetched from anywhere — adding/editing entries is just editing the array, no build step beyond the normal dev reload. All image `src`/`logo`/`photo` paths in them point at `/images/<collection>/...`.
